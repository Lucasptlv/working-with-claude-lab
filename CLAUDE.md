# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`ops-dashboard`: the Marlowe & Finch operations dashboard, used as the sample app for the "Working with Claude" workshop labs (`workshop/`, tickets in `docs/tickets/`). A Spring Boot 3.2 / Java 17 read-only JSON API under `/api` over PostgreSQL, plus a vanilla JavaScript page in `src/main/resources/static/` (no framework, no build step, charts are inline SVG). All data is fictional.

## Commands

```bash
npm install                      # once
npm test                         # Jest + jsdom frontend suite (expect 45 passed)
npx jest src/test/javascript/render.test.js        # one test file
npx jest -t "formatRate"                           # tests matching a name

./mvnw test                      # JUnit 5 suite on H2 (expect 25 tests); no database needed
./mvnw test -Dtest=ClockConfigTest                 # one test class
./mvnw test -Dtest='DashboardControllerTest#<method>'   # one test method

docker compose up -d db          # PostgreSQL 16 on localhost:5432, db/user/password "ops"
./mvnw spring-boot:run           # app on http://localhost:8080 (postgres profile, the default)
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run # in-memory H2, same migrations and seed; no Docker
```

There is no linter configured.

## Rules

- **`pom.xml` dependencies are frozen.** Changes require a CHG ticket. Do not add Maven or npm dependencies.
- **Register every new element id** in `REGISTERED_IDS` in `src/test/javascript/setup/loadApp.js`. `harness.test.js` fails if `index.html` contains an id that is not listed.
- Definition of done for a change: run both `./mvnw test` and `npm test` and report both counts.

## Architecture

**"Today" is pinned to 2026-09-21.** `ops.today` in `application.properties` feeds a fixed `Clock` bean (`ClockConfig`). Every default date range ("last 30 days ending today"), every "days until contract end" figure and every test depends on it, because the seed data covers the 90 days before that date. Inject the `Clock`; never call `LocalDate.now()` without it. The frontend gets "today" from `/api/health`, not from the browser clock.

**Backend.** Plain SQL through Spring JDBC (no JPA) in `DashboardRepository` and `VendorRepository`; thin controllers return Java records. `DateRange.resolve(from, to, clock)` parses the `from`/`to` query params. It deliberately has no validation: a bad date is a 500, `from > to` returns empty, `limit` is unchecked. That gap is ticket TODO-232.

**Database and profiles.** Flyway owns the schema: `db/migration/V1__schema.sql` (schema) and `V2__seed.sql` (data). `V2__seed.sql` is generated by `python3 tools/make_seed.py` (deterministic seed), which also writes `docs/data/deliveries-last-30-days.csv` and the git-ignored `docs/data/ANSWER-KEY.md`. Do not hand-edit the seed. Profile `postgres` is the default; profile `demo` runs the same migrations on H2 in PostgreSQL mode and is what the Java tests use (`@ActiveProfiles("demo")`).

**Frontend.** `app.js` is one IIFE. Everything hangs off `initApp(document, fetchImpl)`, so the same code runs in the browser (started on `DOMContentLoaded`, exposed as `window.OpsDashboard`) and in Jest (exported via `module.exports`). Pure helpers (`formatRate`, `formatMoney`, `barWidths`, `applyPreset`, `daysUntil`) are exported for unit tests. Colours are currently hardcoded in `style.css`, including the SVG chart fills and labels.

**Frontend test harness.** `src/test/javascript/setup/loadApp.js` injects the `<body>` of `index.html` into jsdom, replaces `fetch` with an in-memory fake of every `/api` endpoint (`FIXTURES`, overridable per test, with a `failing` list of paths that answer 500), requires `app.js` fresh and awaits `app.ready`. New endpoints need a case in `createFakeApi`.

**MCP.** `.mcp.json` registers a read-only `postgres` MCP server against the local compose database. Without Docker, use the CSV in `docs/data/` instead.
